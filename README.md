# Cluefolio Studio

An autonomous, evidence-first content agency that produces image-led history stories for
Instagram and Facebook.

This repository is the whole agency: the operating manual, the brand system, eighteen agent
definitions, the templates, the production scripts, the resource register, and the first published
package.

**Post 001 — "The Ship That Never Left the Dock":** the SS *Eastland* disaster, Chicago,
July 24, 1915. 844 dead, in twenty feet of water, twenty feet from shore, on a ship that never left
the dock.

## The site

`site/` is a complete, self-contained static site — no server, no framework, no build step at
runtime. There are three ways to open it, in order of how little can go wrong:

```text
Double-click open-site.bat              # opens the single-file copy, no server at all
```

```text
Double-click start-server.bat           # runs a local server in its own window
```

```text
site/cluefolio.html                     # one 4.3 MB file: every page, every image, inlined
```

```bash
python scripts/build_site.py --serve     # the multi-page site at http://127.0.0.1:8000
```

`start-server.bat` starts the server on port 8080 in a console window you control, and keeps it
running until you close the window. It builds first, so it is always serving current content.

The server listens on **both** `127.0.0.1` and `::1`, so `http://localhost:8080/` and
`http://127.0.0.1:8080/` both work regardless of how Windows resolves localhost. It picks the
next free port if yours is taken and prints the URL it actually used.

To view the site on a phone or another computer on the same network:

```bash
python scripts/build_site.py --serve --lan --port 8080
```

That binds all interfaces and prints your LAN address. It also exposes the files to anyone on
your network, so use it only on a network you trust.

`site/cluefolio.html` is generated by `python scripts/bundle_site.py`. It embeds the stylesheet,
the script, and all six photographs as data URIs, so it issues **zero** network requests and can
be opened from anywhere — a USB stick, an email attachment, a machine with no Python.

The server picks the next free port automatically if 8000 is taken, and prints the real URL it
is using. Add `--port 8080` to choose a different starting port, or `--no-open` to skip the
browser launch.

It includes:

| Page | Contents |
|---|---|
| `index.html` | The post, the story, and what the fact-check changed |
| `post-001.html` | All six images with a lightbox, both captions, alt text, package record |
| `calendar.html` | Eleven posts through January 2027, each with a researched brief |
| `agency.html` | The charter, the roster, the pipeline |
| `brand.html` | Voice, visual identity, specs, hook rubric, editorial standards |
| `process.html` | Every production artifact for Post 001, in pipeline order |
| `resources.html` | The resource register |

The site is generated from the markdown and JSON in this repository, so the documents remain the
single source of truth. Rebuild after editing any doc:

```bash
python scripts/build_site.py
```

To host it publicly, upload the contents of `site/` to any static host. No build environment is
required on the server.

## The agency

Eighteen roles. A core pod runs every project; a specialist bench activates on request.

**Leadership and editorial:** `agency-lead`, `editorial-director`, `story-editor`, `hook-doctor`
**Research and verification:** `research-journalist`, `fact-checker`, `visual-researcher`, `standards-editor`
**Creative production:** `art-director`, `image-producer`, `social-copywriter`
**Growth and audience:** `growth-strategist`, `community-manager`, `analytics-analyst`
**Production and QA:** `qa-lead`
**Bench:** `motion-editor`, `localization-editor`, `paid-media-strategist`

Definitions live in `.opencode/agents/`.

## The pipeline

Eleven stages, six gates, and a rule that nothing moves forward on vibes.

```
0  Brief                  agency-lead + editorial-director
1  Opportunity scan       research-journalist + growth-strategist   → G1 Greenlight
2  Deep research          research-journalist
3  Fact-check             fact-checker (independent)                → G2 Factual lock
4  Visual sourcing        visual-researcher                         → G3 Rights clearance
5  Narrative + hooks      story-editor + hook-doctor                → G4 Story approval
6  Art + render           art-director + image-producer
7  Copy                   social-copywriter + story-editor
8  Growth packaging       growth-strategist + community-manager
9  Standards              standards-editor                          → G5 Clearance
10 QA                     qa-lead                                   → G6 Sign-off
11 Post-publish           analytics-analyst
```

G2 is the important one: no writing starts until every load-bearing claim is verified and every
disputed point has approved handling language. It caught two serious errors in Post 001 before a
single caption was drafted.

## The scripts

Three scripts run the mechanical parts. Everything else is judgment.

```bash
# Download archival assets listed in a post manifest (cached, rate-limit aware)
python scripts/fetch_assets.py --slug first-post

# Render the carousel from assets + render-config.json
python scripts/render_post.py --slug first-post

# Validate the finished package before sign-off
python scripts/validate_post.py --slug first-post

# Build the static site from the markdown and JSON
python scripts/build_site.py --serve
```

Requirements: Python 3 with `Pillow`, `numpy`, and `Jinja2`. Fonts are system fonts (Georgia, Segoe UI).

## Publishing automation

The approved package can be published without copy-paste. GitHub Actions runs
the schedule, the Meta Graph API publishes the carousel and the first comment,
and a JSON ledger prevents double-posting.

```bash
# Check credentials, Page link, and public image hosting
python -m automation.doctor

# Validate a package without calling Meta
python -m automation.publish --post 001 --dry-run

# Publish the post scheduled for today in America/New_York
python -m automation.publish --due
```

On GitHub, `.github/workflows/publish.yml` runs every Wednesday at 17:00 UTC.
The `production` environment is the human approval gate. GitHub Pages hosts the
public images at `PUBLIC_BASE_URL/content/<slug>/images/...`.

Full setup, permissions, token refresh, and troubleshooting:
[`automation/README.md`](automation/README.md).

## Operating rules

- Free and public-domain sources only. Total project spend: **$0**.
- Free models only. No paid APIs without written authorization.
- No secrets in files, logs, or captions.
- Publishing is automated only after a human approves the `production`
  environment. Every run is idempotent and recorded in
  `automation/state/published.json`.
- Authentic imagery first. AI reconstruction only if authentic imagery is unavailable, always
  disclosed. Post 001 used none.
- Every claim traceable. Every image credited. Every asset inspected at full size.

## Reusing this for the next post

1. Create `content/<slug>/`.
2. Write `00-brief.md` from `templates/brief.md`.
3. Build `assets/manifest.json` with `fetch_assets.py` and the `visual-researcher`.
4. Run the pipeline and pass the gates in order.
5. Build `render-config.json` and render with `render_post.py`.
6. Validate with `validate_post.py` before sign-off.
7. Approve `production` in GitHub Actions; the Wednesday workflow publishes and
   records the IDs in the ledger.

The three scripts and the templates are designed to be reused unchanged.
